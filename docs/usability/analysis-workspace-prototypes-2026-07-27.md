# 解析ワークスペース UXプロトタイプ比較

Status: **推奨構成を採用（2026-07-27 利用者確認済み）**
Related: #93, #94, #96, #97, #98

## 目的

Level 4–6で行う前処理、`V_f`・`Phi`候補選択、飽和域fit、`T_i` fit、品質確認を、
一つの「解析」タブへ安全に追加できる配置を比較する。

3案を代表タスクで比較した結果、利用者が実機で4大タブのレイアウトを確認し、
**案Aを骨格に、案Bの大表示と案Cの方式比較を必要時だけ開く推奨構成**を採用した。
Level 4以降はこの骨格へ段階的に追加する。

## 4つの大タブで共通する前提

- 左サイドバーのFolder / Shot / current / sweep voltageは全タブ共通である。
- 起動時は「データ確認」タブを開く。
- 「データ確認」はRaw I–Vと全Raw時系列の見た目・Sweep分割だけを確認する。
  Filtered、微分、fit、解析値は置かない。
- 「解析」は選択した1 Sweepの根拠を確認・調整する場所である。
- 「サマリー」は複数Sweep・shotを集約して比較する場所であり、fit操作を置かない。
- 「Export」は採用済み結果だけから論文用図を作る場所であり、解析値を変更しない。
- 大タブを切り替えただけでは計算しない。再計算は明示操作で開始する。
- 単一Sweepの選択は全タブで同じ`selected_sweep_id`を参照する。
- 入力Revisionと一致しない結果は`stale`とし、採用済み値と同じ見た目にしない。
- 一方式が失敗しても、別方式の成功結果を保持して比較できる。

## 解析タブで扱う段階

| 段階 | 主な操作 | 主な根拠表示 | 後段への影響 |
|---|---|---|---|
| 前処理 | SG窓、次数、再計算 | Raw / Filtered、`dI/dV` | 全解析 |
| 電位 | `V_f`、log交点、微分ピーク候補 | I–V、log、`dI/dV`、候補一覧 | 飽和、`T_i`、品質 |
| 飽和域 | イオン・電子fit範囲 | 直線、外挿、`I_sat`、`R`、`K` | `T_i`、品質 |
| 温度 | Phi方式、評価窓、実行 | PANTA曲線、目的関数、境界解 | 品質 |
| 品質 | 方式比較、レビュー、除外 | flag、差分、履歴、理由 | サマリー、Export |

## 案A｜段階レール＋中央キャンバス＋右インスペクタ

推奨候補。解析の現在地と依存関係を常に見せ、選択中の一段階だけを詳しく操作する。

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ 解析対象: shot / Sweep 10  |  Revision current  |  未保存変更なし          │
├──────────────┬───────────────────────────────────┬─────────────────────────┤
│ 解析段階      │ 根拠キャンバス                    │ 選択段階の設定・候補      │
│              │                                   │                         │
│ ✓ 1 前処理   │  I–V / Filtered / fit / model     │ SG窓、次数               │
│ ! 2 電位     │  表示内容は段階に応じて切替        │ 候補A/B/C、手動値         │
│ — 3 飽和域   │                                   │ 適用 / 元に戻す           │
│ — 4 温度     │  補助図: log / dI/dV / 目的関数   │ 再計算                    │
│ — 5 品質     │                                   │ 状態・警告・根拠           │
├──────────────┴───────────────────────────────────┴─────────────────────────┤
│ 変更の影響: 「Phi変更 → 飽和域以降がstale」 | 履歴 | エラー詳細              │
└────────────────────────────────────────────────────────────────────────────┘
```

### 良い点

- 「どこまで解析済みか」「どこから再計算が必要か」が一目で分かる。
- 右側を段階固有の操作に限定でき、全パラメータを一度に見せずに済む。
- Level 3からLevel 6まで段階を追加しても骨格を変えにくい。
- `valid / review / bad / error / stale / excluded`を段階レールへ表示しやすい。
- 選択候補とプロット上のマーカーを連動させやすい。

### 注意点

- 別段階のグラフを同時比較するには、補助図または一時的な比較表示が必要。
- 右インスペクタの幅が狭いと、fit候補表やエラー説明が窮屈になる。
- 段階移動を「実行」と誤認させない表示が必要。

### 向く使い方

1 Sweepずつ根拠を追い、異常時に前段へ戻って修正する通常解析。

## 案B｜上段ステップバー＋大キャンバス＋下部エビデンストレイ

プロット面積を最優先する案。設定と候補は下部の展開パネルへまとめる。

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ [前処理 ✓] → [電位 !] → [飽和域 —] → [温度 —] → [品質 —]                 │
├────────────────────────────────────────────────────────────────────────────┤
│                                                                            │
│                     大きな主プロット                                       │
│             I–V / log / dI/dV / model を切替・重畳                         │
│                                                                            │
├────────────────────────────────────────────────────────────────────────────┤
│ 根拠・設定トレイ  [候補] [設定] [目的関数] [警告] [履歴]                   │
│ 候補A 14.2 V  valid  | 候補B 15.1 V review | 手動値 ...   [適用]           │
└────────────────────────────────────────────────────────────────────────────┘
```

### 良い点

- I–Vや目的関数を大きく表示でき、曲線形状の確認に強い。
- 横長ディスプレイでも縦の視線移動が中心で分かりやすい。
- 下部トレイを閉じればプロットへ集中できる。
- 現在の「上にI–V、下に操作」という構造から移行しやすい。

### 注意点

- 設定を調整しながらグラフを見ると、下部トレイの高さが頻繁に変わる。
- 段階ごとの完了・stale状態が上部の狭いバーへ集中する。
- 複数候補の比較表と長い品質説明を同時に置きにくい。
- ノートPCの縦解像度では主プロットとトレイが競合する。

### 向く使い方

曲線形状を大きく見ながら、一つの解析方式を順番に調整する作業。

## 案C｜方式比較ボード＋詳細インスペクタ

対数法・微分法、Raw・Filteredなどの並行比較を最優先する案。

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ 解析対象: Sweep 10        [前処理] [電位] [飽和域] [温度] [品質]           │
├──────────────────────────────────────────────┬─────────────────────────────┤
│ 比較ボード                                    │ 選択カードの詳細             │
│ ┌─────────────────┐ ┌─────────────────┐      │ 候補、fit範囲、パラメータ    │
│ │ Filtered / log  │ │ Filtered / dI/dV│      │ 目的関数、警告、履歴          │
│ │ Phi / T_i / 状態│ │ Phi / T_i / 状態│      │ [採用] [除外] [再計算]       │
│ └─────────────────┘ └─────────────────┘      │                             │
│ ┌─────────────────┐ ┌─────────────────┐      │                             │
│ │ Raw / log       │ │ Raw / dI/dV     │      │                             │
│ └─────────────────┘ └─────────────────┘      │                             │
├──────────────────────────────────────────────┴─────────────────────────────┤
│ 選択した2方式のグラフ差分・候補差・品質差                                  │
└────────────────────────────────────────────────────────────────────────────┘
```

### 良い点

- 4方式の結果と部分失敗を同じ粒度で比較できる。
- 「どの方式を採用したか」を明示しやすい。
- 方法間の不一致をレビューするLevel 6後半に強い。
- サマリーへ送る代表値の根拠を残しやすい。

### 注意点

- Level 4の`V_f`候補選択だけを行う段階では情報量が多すぎる。
- 小さいカードでは詳細なI–V形状を読み取りにくい。
- 方式×段階の状態管理を初見利用者が理解するまで時間がかかる。
- 解析順序が見えにくく、未実行段階のカードが大量に並びやすい。

### 向く使い方

解析が一通り完了した後の方式比較、レビュー、採用方式決定。

## 代表タスクによる比較

| 代表タスク | 案A | 案B | 案C |
|---|---:|---:|---:|
| cleanデータで前処理から`T_i`まで順番に進む | ◎ | ◎ | △ |
| log交点失敗・微分法成功の部分成功を理解する | ○ | △ | ◎ |
| Phi変更でどの後段がstaleになったか確認する | ◎ | ○ | ○ |
| fit範囲を動かしながらI–Vを大きく見る | ○ | ◎ | △ |
| 4方式の値・品質・採否を比較する | ○ | △ | ◎ |
| 初見利用者が次の操作を理解する | ◎ | ○ | △ |
| Level 3から段階的に実装する | ◎ | ○ | △ |

`◎`は主用途に適合、`○`は補助UIで対応可能、`△`は画面切替や情報過多の対策が必要。

## 推奨構成

**案Aを解析タブの骨格にし、案Bの大きな主プロット、案Cの方式比較を必要時に開く**
段階的な構成を推奨する。

1. 通常時は案Aで、左の段階レール、中央の大プロット、右の設定・候補を表示する。
2. 中央プロットは拡大でき、案Bと同じ大きさでfit範囲を調整できる。
3. 品質段階または「方式比較」を押したときだけ、中央を案Cの比較ボードへ切り替える。
4. Raw全時系列とSweep分割は「データ確認」タブに残し、解析タブへ重複配置しない。
5. どの表示でもRevision、状態、変更の影響、明示的な再計算ボタンを固定位置に置く。

この構成なら、日常の順次解析を複雑にせず、4方式比較が必要な場面だけ情報密度を上げられる。

## 利用確認シナリオ

最終決定前に、少なくとも次のデータで確認する。

1. **clean**: log法・微分法とも候補が一つに定まる。
2. **noisy**: 候補が複数あり、RawとFilteredで結果がずれる。
3. **partial failure**: log交点は失敗するが微分ピークは成功する。
4. **boundary solution**: `T_i`最適値が探索上下限付近になる。
5. **manual review**: 利用者が候補またはfit範囲を変更し、下流がstaleになる。

各シナリオで次を観察する。

- 次に何をすべきか説明なしで分かるか。
- 値ではなく根拠曲線を見て候補を選べるか。
- 自動値、手動値、旧Revisionを混同しないか。
- 一方式の失敗で他方式の成功を見失わないか。
- 再計算範囲と変更の影響を予測できるか。
- 除外理由を入力し、後から復元できるか。

## 採用決定

比較した選択肢は次の4つ。

1. **案A**をそのまま採用する。
2. **案B**を採用し、プロット面積を最優先する。
3. **案C**を採用し、常時方式比較を優先する。
4. **推奨構成（Aを骨格、Bの拡大、Cを必要時表示）**を採用する。
